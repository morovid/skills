# Resume `spec` from a review return

1. Read `review-report.md`, `review-rework.md`, or equivalent supplied findings, alongside the linked request, reviewed artifacts, and current versions. Treat legacy skill names in a packet as labels for the corresponding authoring phases. Reconcile stale locators with current records before editing; do not replay a correction blindly over newer confirmed work. Preserve `RV` finding and `RW` task IDs, dependencies, and history. The review report owns finding definitions and closure. A diagnosis or recommendation does not authorize a new product rule.
2. Start at the earliest affected authoring phase, and follow the packet's dependencies. Treat an upstream authoring task as usable for dependent drafting only when the required confirmed output and its gate are current; do not wait for closure unless the dependency actually requires reviewer action.

   | Cause | Action in `spec` |
   | --- | --- |
   | Objective, actors, scope, exclusions, or constraints are unclear | Reopen intake for the affected boundary. Record any requester decision and follow its effects through discovery and refinement. |
   | Baseline, dependency, impact, preservation rule, or intended behavior is missing or unsupported | Reopen targeted discovery. Repair affected `E/CB/I/B` and canonical `D/A/Q` records. Investigate available evidence and ask only for a material choice or unavailable input that remains. Refine the resulting confirmed behavior. |
   | Confirmed behavior exists but is misrepresented or not verifiable | Start at refinement. Give the refiner the affected `US/SC/FR/NFR/AC` records, coverage, traceability, and Definition of Done repairs with their confirmed sources. Do not restart intake or discovery for an isolated acceptance gap. |
   | Independent validation, approvals, or assembly alone need work | Resume at the [review phase](review.md) or obtain the missing input from the designated authority. Do not revise authoring artifacts to simulate a review outcome. |

3. Run the same discovery, question, and refinement loop for the affected work. Preserve usable independent records and reconcile related records even if the packet did not list them all. Recheck the affected gates and explicitly invalidate affected downstream artifacts, review verdicts, and version-bound approvals. An open review-local finding can still block engineering even when authoring is ready.
4. Record the author response in the packet's **Return submission and revalidation** section and, for another correction attempt, its **Shared attempt history**. For each `RV/RW` (or supplied finding locator), include the attempted correction, input/output paths and exact versions, changed IDs, authority or evidence, actual authoring gate results, downstream rechecks, and any remaining blocker. If there is no writable packet, save the same response beside the authoring artifacts (e.g. `spec-rework-response.md`), link it to the original findings and history, and supply it at re-review. Do not duplicate or change the reviewer-owned finding definitions or recheck results.
5. Submit completed author corrections as **Addressed—pending recheck**. Record any incomplete or stalled work as **Blocked** with the exact unblock action and owner/source if known. Hand the updated artifacts, response location, and affected checks to a fresh independent reviewer within `spec`. Only independent review can close or reopen findings and restore engineering readiness.

## Respect the stalled-loop guard

Read the shared attempt history before retrying. After two consecutive unsuccessful review rechecks of the same blocking finding without material progress (excluding the original review and author self-checks), stop that correction path. Keep independent work going and save the affected phase's blocker report with attempted fixes, affected records, and exact unblock action. Changing phases, task IDs, or sessions does not reset the count. Resume only when new evidence, a confirmed decision, restored access, or another documented change addresses the blocker. Record why it permits a different action; review records recheck outcomes and manages the count.
